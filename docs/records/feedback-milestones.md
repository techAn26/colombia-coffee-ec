# フレームワークへのフィードバック: マイルストーン設計

記録日: 2026-05-15

---

## 課題

ECサイトを1つの大きなゴールとして開発すると、完成までの道のりが長く、以下の問題が発生する:

- 「完成」の実感が得にくく、モチベーションが下がる
- 途中で方向転換しにくい
- 小さく検証する機会がない
- ポートフォリオとして「途中段階」でも見せられるものがない

## 改善提案: フェーズ別マイルストーン

最終ゴール（ECサイト完成）に向けて、技術レベルの切り口でマイルストーンを設定し、**各フェーズで「小さな完成品」を作りきる**。

```
Phase 1: ホーム & LPページのみ
  → 「こういうサイトを作りたい」が伝わるレベル
  → HTML/CSS/デザインの基礎

Phase 2: 静的情報で商品一覧画面を追加
  → データベースなしで商品を表示。コンポーネント設計の基礎
  → フロントエンドの基礎

Phase 3: ログイン & お気に入り機能
  → 認証・DB連携の基礎。ユーザーごとのデータ管理
  → バックエンドの基礎

Phase 4: 決済機能
  → カート・Stripe連携・注文管理
  → 外部サービス連携の応用
```

## メリット

1. **各フェーズが「完成品」**: Phase 1だけでもLPとして見せられる
2. **段階的に技術レベルが上がる**: HTML → コンポーネント → DB → 外部連携
3. **途中で止められる**: Phase 2で止めても「商品紹介サイト」として成立
4. **検証しやすい**: 各フェーズ終了時にユーザーテスト・フィードバック可能
5. **ポートフォリオに使いやすい**: 「Phase 1→2→3→4と成長した過程」自体がストーリー

## フレームワークへの反映案

development-framework.mdの「Phase 5: 開発」セクションに、Chapter形式に加えて**マイルストーン（Phase）の概念**を追加する。

```
開発の全体構造:
  Phase（マイルストーン）= 技術レベル別の「完成品」単位
    └── Chapter（学習テーマ）= 概念の理解 + 実践
         └── Step（タスク）= 具体的な実装
```

## 次回のプロジェクトで試すこと

- 最初にPhaseを定義し、各PhaseのゴールとデリバブルType（成果物）を明確にする
- Phase完了ごとにデプロイ・レビュー・振り返りを行う
- Phaseをまたぐ際に、前Phaseで作ったものを壊さないことを確認する（リグレッション）
