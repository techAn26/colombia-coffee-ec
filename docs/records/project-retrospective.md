# プロジェクト振り返り — Colombia Coffee ECサイト

実施日: 2026-05-15

---

## プロジェクトストーリー（田中さんが語れるようになるべき形）

### 課題

コロンビアの高品質なスペシャリティコーヒー豆が、既存の流通では農園のストーリーごと消費者に届けられない。大手ECでは産地情報が薄く、こだわりで豆を選ぶ体験ができない。

### 動機

コロンビア留学時代に知った農園主たちの想いを、日本の消費者に届けたかった。農園の「顔が見える」ECサイトを作ることで、コーヒー豆の販売だけでなく、コロンビアと日本をつなぐ架け橋にしたい。

### 工夫

- **ITスキルなしからのスタート**: AIを活用したバイブコーディングで開発。プログラマーの友人（鈴木さん）にコードレビューを依頼し品質を担保
- **理解駆動開発**: AIが書いたコードを「動いたから次」ではなく「理解したから次」で進めた
- **Chapter形式**: 12章の講義＋実践構成で、概念を理解してから手を動かすスタイル
- **農園ストーリー**: 商品情報だけでなく、農園の背景・想い・こだわりを伝えるUI設計
- **セキュリティ重視**: RLS（行レベルセキュリティ）、Webhook署名検証、三重ガードなど多層防御

### 困難

- **LINEログインの技術的制約**: SupabaseがLINEをネイティブサポートしておらず、カスタムOIDCでの実装に方針変更
- **Next.js 16の破壊的変更**: middleware→proxyへのリネームなど、最新バージョン特有の対応が必要
- **Server Actionsとテストの分離**: `"use server"` ファイル内の純粋関数をテストするため、ロジックの分離が必要だった
- **バリエーション設計**: 当初は1商品1価格の想定だったが、グラム別バリエーションの要件追加でDB設計を拡張

### 結果

- **全16画面**のECサイトを構築（公開3 + 認証1 + 会員7 + 管理5）
- **9テーブル**のDB設計 + **25のRLSポリシー**でセキュリティ確保
- **Google/LINE OAuth**認証、**Stripe決済**、**Webhook注文処理**を統合
- **商品管理画面**（CRUD + 画像アップロード + 在庫管理）
- **レビュー機能**（購入済み商品のみ投稿可能、RLSで制御）
- **12のユニットテスト**全通過、**43の手動テストシナリオ**を作成
- **12章の開発記録** + **480問の理解度テスト**

### 学び

- AIは強力だが、品質の担保には人間のレビューが不可欠
- 技術がなくても「何を解決したいか」が明確なら、形にできる
- 「動くもの」を作ることより「理解すること」の方が、長期的に価値がある
- セキュリティは後付けではなく最初から設計に組み込むべき
- フレームワーク（開発プロセス）自体も、実践を通じて改善していくもの
